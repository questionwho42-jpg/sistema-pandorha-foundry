# 📜 Regras de Consistência para Sistemas de RPG

Ao construir ou validar um sistema de RPG, estas regras garantem que as mecânicas façam sentido interno e funcionem na prática de jogo.

---

## Regra 1: Coerência de Dados

**O tipo de dado escolhido deve servir ao propósito do sistema.**

### Validação:

- ✅ d20: Aceita grande variância e aleatoriedade heroica?
- ✅ Pool de d6: A quantidade de dados escala de forma razoável (2-10)?
- ✅ 2d6: As probabilidades de curva são desejadas (extremos raros)?

### Correção Típica:

> Se seu sistema é gritty/realista, evite d20 puro (muita sorte). Se é heroico, evite pools muito pequenos.

---

## Regra 2: Economia de Ações

**Turno de combate deve ter clareza sobre o que se pode fazer.**

### Validação:

- ✅ Está claro quantas ações um personagem tem por turno?
- ✅ Ações bonus/reações/ações livres estão definidas?
- ✅ O turno pode ser resolvido em menos de 2 minutos de jogo?

### Correção Típica:

> Crie uma lista de 3-5 ações permitidas por turno. Exemplo: "1 ação principal + 1 movimento + 1 reação".

---

## Regra 3: Curva de Aprendizado Apropriada

**A complexidade deve combinar com o público-alvo.**

| Público    | Complexidade Aceitável                       |
| ---------- | -------------------------------------------- |
| Iniciantes | 1 página de regras rápidas, criação em 5 min |
| Misto      | Core simples, opções avançadas modulares     |
| Veteranos  | Táticas profundas, combos, builds            |

### Correção Típica:

> Crie um "Quick Start" de 1-2 páginas mesmo para sistemas complexos.

---

## Regra 4: Loop de Jogo Definido

**O sistema deve deixar claro o que jogadores fazem na prática.**

### Validação:

- ✅ Existe um ciclo claro (exploração → conflito → recompensa → downtime)?
- ✅ Cada fase do loop tem suporte mecânico?
- ✅ Jogadores sabem quando rolar dados e quando narrar livremente?

### Correção Típica:

> Escreva 1 parágrafo: "Em [Sistema], jogadores passam a maior parte do tempo [fazendo X], interrompido por [Y], recompensados com [Z]."

---

## Regra 5: Progressão Significativa

**Subir de nível deve SENTIR-SE diferente, não apenas números maiores.**

### Validação:

- ✅ Novos níveis desbloqueiam opções NOVAS (não apenas +1)?
- ✅ A diferença entre nível 1 e nível máximo é perceptível na narrativa?
- ✅ Progressão existe fora de combate (perícias, influência, recursos)?

### Correção Típica:

> A cada 3-5 níveis, adicione uma habilidade que mude fundamentalmente o que o personagem PODE FAZER.

---

## Regra 6: Resolução de Conflitos Coerente

**Combate, social e exploração devem usar lógica similar.**

### Validação:

- ✅ Se combate usa d20+mod, social também usa?
- ✅ Condições de status afetam todos os pilares (cego afeta percepção e combate)?
- ✅ Existe mecânica para conflitos não-violentos (debates, perseguições, investigações)?

### Correção Típica:

> Use a mesma estrutura: "Rolar [dado] + [modificador] vs [dificuldade/oposição], interpretar resultado".

---

## Regra 7: Customização vs Padronização

**Escolhas do personagem devem ser significativas SEM quebrar o jogo.**

### Validação:

- ✅ Existem escolhas "trap" (opções objetivamente ruins)?
- ✅ Existe uma build "ótima" que invalida outras escolhas?
- ✅ Customização permite identidade única ou é apenas números?

### Correção Típica:

> Playtest com 3 builds diferentes. Se uma sempre vence, rebalanceie. Se são idênticas em prática, adicione distinção.

---

## Regra 8: Escala de Poder Clara

**O sistema deve definir os limites do que personagens podem fazer.**

### Validação:

- ✅ Nível 1 pode fazer X, nível máximo pode fazer Y - está documentado?
- ✅ A progressão é linear, exponencial ou tiers discretos?
- ✅ NPCs seguem as mesmas regras ou têm simplificações?

### Correção Típica:

> Crie uma tabela: "Tier 1 (níveis 1-5): heróis locais. Tier 2 (6-10): heróis regionais. Tier 3 (11+): lendas".

---

## Regra 9: Playtest Obrigatório

**Teoria não substitui mesa de jogo real.**

### Métricas de Playtest:

| Métrica                        | Alvo Saudável                                      |
| ------------------------------ | -------------------------------------------------- |
| Tempo de turno de combate      | < 2 minutos por jogador                            |
| Tempo de criação de personagem | Alinhado com público-alvo                          |
| Morte de personagem            | Possível mas não trivial (a menos que intencional) |
| Habilidades "nunca usadas"     | < 20% do total                                     |

### Correção Típica:

> Registre 3 sessões de playtest. Anote: o que travou, o que foi pulado, o que causou discussão de regras.

---

## Regra 10: Documentação Clara

**O manual deve ser jogável, não apenas legível.**

### Checklist de Documentação:

- ✅ Índice funcional (encontrar regra em < 30 segundos)?
- ✅ Exemplos para cada mecânica complexa?
- ✅ Quick reference / cheat sheet disponível?
- ✅ Glossário de termos técnicos?
- ✅ Fluxogramas para combate/resolução?

### Correção Típica:

> Dê o manual para alguém que não sabe nada do sistema. Se não conseguir criar personagem sozinho, reescreva.

---

## 📋 Checklist de Validação Final

Antes de finalizar o sistema, responda:

| #   | Pergunta de Validação                             | ✅/❌ |
| --- | ------------------------------------------------- | ----- |
| 1   | O tipo de dado serve ao tom do sistema?           |       |
| 2   | Turnos de combate são resolvíveis em < 2 min?     |       |
| 3   | Existe Quick Start para iniciantes?               |       |
| 4   | O loop de jogo está explícito?                    |       |
| 5   | Subir de nível dá opções NOVAS?                   |       |
| 6   | Conflitos não-violentos têm suporte?              |       |
| 7   | Não existem builds "trap" óbvias?                 |       |
| 8   | Escala de poder está documentada?                 |       |
| 9   | Foi playtestado com 3+ sessões?                   |       |
| 10  | Alguém de fora consegue criar personagem sozinho? |       |

Se algum item for ❌, volte ao pilar correspondente e refine.

## 🔧 Ferramentas de Balanceamento

### Cálculo de DPR (Damage Per Round)

```
DPR = (Chance de Acerto) × (Dano Médio)

Exemplo d20:
- Bônus de ataque +5, AC inimiga 15
- Chance de acerto = (20 - 15 + 5 + 1) / 20 = 55%
- Dano médio de 1d8 = 4.5
- DPR = 0.55 × 4.5 = 2.475
```

### Comparativo de Builds

| Build   | DPR    | Survivability | Utility | Nota              |
| ------- | ------ | ------------- | ------- | ----------------- |
| Tank    | Baixo  | Alta          | Média   | Proteção do grupo |
| Striker | Alto   | Baixa         | Baixa   | Dano focado       |
| Support | Nenhum | Média         | Alta    | Amplifica outros  |
| Hybrid  | Médio  | Média         | Média   | Flexível          |

Se todas as colunas de uma build são "Baixo", ela é trap. Rebalanceie.
